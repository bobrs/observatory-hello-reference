# Hello Observatory

A real, independently runnable Hello World reference app whose version is immediately visible and whose packaged bytes have an externally checkable identity. The page and `/version` describe the same startup-verified release.

AO-INC-003A is a custom local Node profile: native HTTP, HTML/CSS and tests. No React/Vite/Cloudflare runtime or deployment configuration is needed. The three fixed release descriptors produce 1.0.0, 1.1.0 and 1.2.0 packages. The repository's default/reference version is 1.2.0; each package has its own baked version.

The Product Sponsor directly authorized Step A in the Codex session after approving the proposed public CC0 repository. [Dev proposal](https://github.com/bobrs/Application-Observatory/issues/7#issuecomment-6485115867) and [PM concurrence](https://github.com/bobrs/Application-Observatory/issues/7#issuecomment-6485169603) supply rationale. This is Dev's attributed transcription, without a public permalink for the direct instruction; it is not independent GitHub authentication of the Sponsor role.

The initial main baseline contains only README and LICENSE. Implementation is submitted by feature PR and needs PM review and separate Sponsor merge authorization. Step B (Observatory bridge, destination lifecycle/control and side-by-side observations/rollback) is not authorized.

The runtime is read-only and loopback-only. A launcher first checks bytes against the digest index outside the package; internal manifest verification is additional evidence, not self-attestation. Index trust comes from reviewing/pinning its source/evidence, not merely from its being on disk. A stage label is context and never changes the version or content identity. Production context is permitted only with a prominent disposable-demo designation.
